## v4：关系图 hover 变灰 bug 修复

用户反馈：关系图 hover 某节点时，总有一个非一级链接的节点不变灰，且选不同节点时不变灰的那个还不是同一个。

### 根因（三层）
1. **CSS 变量在 canvas 无效** — `graphData()` 里节点 color.background 用 `"var(--paper)"`、font.color 用 `"var(--ink)"`、边 font.color 用 `"var(--muted)"`。canvas 的 fillStyle 不支持 `var()`，颜色解析失败。
2. **形状透明度走 `color.opacity` 而非顶层 `opacity`** — 查 vis-network 9.1.9 源码：`t.globalAlpha=e.opacity` 只用于 circularImage 的图片绘制（位置 211873）；形状/边框/背景透明度用的是 `r.opacity`（即 color 对象的 opacity 字段，位置 227875）。原代码只设顶层 opacity，边框/背景不变灰。
3. **对象引用共享导致 vis 跳过重绘** — 原 hover 代码 `color:o.color` 传的是 snap 里的同一引用，vis 用引用比较判断"是否变化"来决定是否重绘节点，引用没变就跳过，导致某个节点样式不更新（不变灰的那个随 hover 目标变化而不同）。

### 修复
- `reader/app.js`（`index.html` 配套）：`graphData()` 开头用 `getComputedStyle` 解析 `--paper`/`--ink`/`--muted` 为实际颜色值，节点/边的 color/font 全部用解析后的值
- `renderGraph()` hover/blur 重写：预计算邻居表 `nbr`，预计算 active/dim 两套样式，用 `JSON.parse(JSON.stringify())` 深拷贝，dim 版 color 对象加 `opacity:0.12`（让边框/背景也变灰），每次 update 都传新对象引用

## v5：修复 `百年孤独-阅读器.html`（独立单文件版）的关系图 hover bug

用户反馈 `百年孤独-阅读器.html` 仍有同样问题：非一级节点不变灰、一级节点名字不显示。

### 根因（与 v4 不同）
该文件是独立单文件应用，内联了全部 JS，且有独立的 graph 实现，与 `app.js` 的修复不同步。

1. **`opacity` 对 `circularImage` 节点不可靠** — 有些头像图片在 `opacity: .15` 下仍然满透明度渲染
2. **hover 节点自身也在邻居集合中** — `const nb = new Set([hid])` 使悬停节点自己始终不灰，用户误以为它是"不变灰的非一级节点"
3. **DataSet.update 深合并导致字体状态错乱** — 非邻居用 `font:{color:"transparent"}`（部分对象），邻居用 `font:o.font`（完整对象），深合并产生不完整中间状态，快速悬停时 label 不显示
4. **blurNode 与 hoverNode 时序竞争** — 快速连续悬停不同节点时，blur 恢复和下一轮 hover 互相覆盖

### 修复方式
- 放弃 `opacity`，改用颜色淡化（`greyColor()` 函数将 hex 混白）
- 悬停节点用加粗高亮边框（`borderWidth:5`），邻居保留原色，非邻居灰色边框 + 浅灰背景
- font 始终用展开对象 `{...o.font, color:"transparent"}`，避免深合并猜测
- 加 `_restoring` 标志 + `setTimeout` 防 blur/hover 时序竞争

用户反馈 v5 仍有两个问题：二级节点应隐藏而非变灰、部分一级节点标签还是不显示。

**根本解决方案**：不再操作 font/opacity 等复杂嵌套属性，改用 vis-network 原生支持的 `hidden: true/false`:
- 二级节点 → `{hidden: true}`，vis-network 直接跳过渲染，节点和连线全部消失
- 悬停节点 → `{hidden: false, borderWidth:5, color: ...}` 高亮
- 一级邻居 → `{hidden: false}` 保持原样（完全不碰 font）
- 连线 → 仅保留两端都在可见集内的连线
- blur → `{hidden: false}` 恢复全部
- font 对象全程不碰，根除深合并导致的标签丢失问题
